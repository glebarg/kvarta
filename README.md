# Кварта — лендинг кофейной обжарки

React/Vite frontend и FastAPI backend, запускаемые через Docker Compose. Сайт показывает ассортимент и информацию о кофейной подписке, принимает заявки и сохраняет их в SQLite. В конфигурации предусмотрен необязательный Telegram polling-процесс для подписок и уведомлений, если соответствующие файлы бота включены в backend.

## Возможности

- Адаптивный сайт кофейной обжарки «Кварта».
- Форма заявки: имя, телефон, интерес и необязательный комментарий.
- Проверка и нормализация белорусского номера на backend.
- Защита от повторной заявки с того же номера в течение 10 минут.
- Сохранение заявок и рекламных меток в SQLite.
- Сбор UTM-параметров, `gclid`, `yclid`, адреса текущей страницы и `referrer`.
- Docker Compose для сборки и запуска frontend и backend.
- Nginx внутри frontend-контейнера обслуживает статические файлы и проксирует API-запросы в backend.
- Необязательный Caddy-профиль для HTTPS с автоматическим получением TLS-сертификата.
- Необязательный Telegram polling-контейнер, если в backend присутствуют `run_telegram_bot.py` и код бота.

Сайт не принимает онлайн-оплату. Форма отправляет заявку для последующей связи с клиентом.



В локальном режиме сайт доступен по адресу `http://127.0.0.1:8080`. Backend не публикует порт в интернет: запросы к `/api/` проходят через Nginx. В production публичным входом становится Caddy, который принимает HTTP/HTTPS и передаёт запросы frontend-контейнеру.

## Что нужно установить

Для локальной разработки и сервера нужен **Docker Engine и Docker Compose v2**. На Windows проще всего использовать Docker Desktop с включённым WSL 2. Node.js и Python на хост-машине для запуска приложения не требуются: зависимости устанавливаются при сборке контейнеров.

Для production нужен VPS с Linux, публичным IP-адресом и доменом, DNS которого указывает на этот IP.

## Запуск локально через Docker

Команды ниже выполняются из корня репозитория — в папке, где находится `compose.yaml`.

### 1. Подготовить переменные окружения

Windows PowerShell:

```powershell
Copy-Item .env.docker.example .env
```

Linux/macOS:

```bash
cp .env.docker.example .env
```

Откройте `.env` и для локального запуска установите, например:

```dotenv
DOMAIN=localhost
FRONTEND_ORIGINS=http://localhost,http://127.0.0.1
HTTP_PORT=8080
TELEGRAM_BOT_TOKEN=
TELEGRAM_API_TIMEOUT=5
```

Не добавляйте `.env` в Git. Для локального запуска Telegram-токен можно оставить пустым.

### 2. Проверить изображения

Сайт ссылается на изображения в `frontend/public/images/`. Убедитесь, что изображения проекта находятся в этой папке до сборки Docker-образа. Если в вашем репозитории есть `download-images.ps1`, запустите его из корня проекта в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\download-images.ps1
```

Если скрипта нет или изображения уже добавлены, этот шаг пропустите. Docker не может включить файлы, которых нет в рабочей копии.

### 3. Собрать и запустить

```bash
docker compose up -d --build
```

После успешного запуска откройте:

- Сайт: `http://127.0.0.1:8080`
- Проверка backend через Nginx: `http://127.0.0.1:8080/health`
- Swagger API: `http://127.0.0.1:8080/docs`

Первый запуск может занять несколько минут, пока Docker скачивает базовые образы и устанавливает зависимости.

### 4. Важная настройка frontend API URL

Frontend должен отправлять запросы на тот же домен, с которого загружен сайт, чтобы Nginx мог проксировать их в FastAPI. В `frontend/src/App.tsx` строка с `API_URL` должна использовать nullish coalescing (`??`), а не логическое ИЛИ (`||`):

```tsx
const API_URL = import.meta.env.VITE_API_URL ?? 'http://127.0.0.1:8000'
```

Docker передаёт пустое значение `VITE_API_URL`, поэтому в контейнерной production-сборке запрос будет относительным, например `/api/lead`. Для локального запуска через Vite в `frontend/.env` можно оставить `VITE_API_URL=http://127.0.0.1:8000`.

### 5. Остановить приложение

```bash
docker compose down
```

Данные SQLite сохраняются в именованном Docker volume и не удаляются при обычном `docker compose down`. **Не используйте `docker compose down -v`, если не хотите удалить volume с базой данных.**


## Проверка работы

1. Откройте сайт по локальному адресу или production-домену.
2. Отправьте заявку с тестовыми данными.
3. Убедитесь, что форма показала подтверждение.
4. Проверьте backend: `GET /health` должен вернуть `{"status":"ok"}`.
5. Проверьте, что запись появилась в таблице `leads`.
6. Если Telegram включён, проверьте получение сообщения у подписчика бота.

`POST /api/lead` принимает `name`, `phone`, `interest`, `comment` и поля атрибуции. Возможные ответы: `201` — заявка сохранена; `409` — повторная заявка с того же номера в пределах 10 минут; `422` — данные не прошли валидацию. Swagger доступен по `/docs`.

## База данных и резервные копии

В контейнере backend SQLite хранится по пути `/data/kvarta.db`. Этот каталог подключён к именованному Docker volume `kvarta_data`, поэтому файл базы переживает пересоздание контейнера и обновление образа.

### Создать резервную копию

```bash
mkdir -p backups
docker compose exec -T backend python -c "import sqlite3; src=sqlite3.connect('/data/kvarta.db'); dst=sqlite3.connect('/tmp/kvarta-backup.db'); src.backup(dst); dst.close(); src.close()"
docker compose cp backend:/tmp/kvarta-backup.db ./backups/kvarta-$(date +%F).db
docker compose exec -T backend rm -f /tmp/kvarta-backup.db
```

Храните резервные копии вне сервера и ограничивайте к ним доступ: в базе есть персональные данные клиентов. Периодически проверяйте, что копию действительно можно восстановить.

## Обновление приложения

После отправки новых изменений в Git на сервере выполните:

```bash
git pull
docker compose --profile production up -d --build
```

Если используется Telegram polling:

```bash
git pull
docker compose --profile production --profile telegram up -d --build
```

После обновления проверьте статус и логи. Обычное обновление не должно удалять volume базы данных.

## Полезные команды

```bash
# Состояние контейнеров
docker compose ps

# Логи всех обычных сервисов
docker compose logs -f

# Логи отдельного сервиса
docker compose logs -f backend
docker compose logs -f frontend

# Пересобрать и перезапустить
# (для production добавьте --profile production)
docker compose up -d --build

# Остановить сервисы, сохранив данные
docker compose down

# Посмотреть используемые Docker volumes
docker volume ls

# Запустить тесты backend внутри одноразового контейнера
docker compose run --rm --no-deps backend pytest
```

## Безопасность

- Не коммитьте `.env`, токены, дампы SQLite и данные клиентов.
- Не публикуйте порт backend `8000` напрямую в интернет.
- Используйте HTTPS в production.
- Ограничьте доступ к VPS по SSH и обновляйте операционную систему и Docker.
- Делайте резервные копии базы данных и храните их отдельно от VPS.
- Проверяйте, кто имеет доступ к заявкам и Telegram-уведомлениям.
- Swagger `/docs` сейчас доступен через публичный домен. Если в production он не нужен, закройте его в Nginx/Caddy или настройте доступ отдельно.
- Значения `VITE_*` не являются секретами: они встраиваются в frontend bundle.


Основные сервисы:

| Сервис | Назначение | Публикуемые порты |
|---|---|---|
| `frontend` | Статические файлы и reverse proxy для API | `127.0.0.1:8080` для локальной проверки |
| `backend` | FastAPI и работа с SQLite | Только внутри Docker-сети |
| `caddy` | HTTPS и публичный вход на сервере | `80`, `443` — профиль `production` |
| `telegram-bot` | Обработка команд бота, если модуль включён | Нет — профиль `telegram` |
